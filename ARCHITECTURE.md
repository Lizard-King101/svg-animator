# Editor Architecture

## Working principle

**Clean boundaries. One source of truth. Reusable behavior. Polished interactions.**

Architecture is part of feature delivery. Pages and shells compose; components own cohesive views and local interactions; scoped services own shared state and commands; pure helpers own reusable calculations. Duplicate behavior should be consolidated at the second real consumer, while view-specific presentation remains local. Refactors must preserve layout topology, input behavior, mutation boundaries, and persisted compatibility.

## Ownership rules

Artwork and bone rows share `InlineRenameDirective` for native text drafts outside Angular change detection. Typing does not modify the document; Enter or blur completes once, Escape discards, and the owning layer command rejects stale document/revision sessions. Artwork rename commits as metadata. Layer rows reuse their already-known parent for clipping badges and visibility labels instead of recursively searching the document.

`path-outline.ts` caches derived outline geometry per live path and rounding mode. Exact scalar geometry, topology, stroke, and section inputs invalidate the cache, including in-place previews and rig deformation; metadata and paint changes reuse geometry. The cache is bounded, weakly held, and never serialized. Bounds calculations reuse the existing hull for automatic transform origins, and identity/translation matrices skip origin geometry entirely.

`AnimationPlaybackService.activeAnimation` resolves the scene or source while keeping `selectedSVG` stable. Playback owns context identity and separate session playheads. Its context-change event cancels timeline drafts and key selection before routing changes. Timeline queries, canvas/paint key writes and detached inspection use this context. Scope checks apply to key creation and paste; sources cannot recursively contain composition.

`compositionChannels` resolves links once per plan/compiler revision into base/direct channels with ordered local action windows. The shared interval helper defines start-inclusive/end-exclusive activation. Outside a block, the base/direct channel evaluates at scene time. Distinct sources may overlap when their enabled, nonempty channels do not conflict. Frame geometry and point deformation share an exclusive geometry domain; placements of the same source remain exclusive even when empty. Placement, duration, import and mutation validation share the overlap helper. Before committing, the mutation boundary asks playback to reject conflicting composition edits and restore the last committed animation; this covers paste, paint restoration and later channel additions without saving invalid data or adding an undo step. ActionPlacementRowsComponent participates directly in the dope-sheet grid with display:contents and explicit 64px rows; the timeline viewport accounts for placement heights before virtualizing layer rows. ActionPlacementBlockComponent owns temporary move/trim pointer drafts, capture/cancellation and keyboard nudges; placement-trimming.ts computes rate/repeat-aware trims with the opposite scene edge fixed, reusing timeline conversion and time quantization. Runtime 1.1 guards optional same-channel, non-nested `actionWindows` with `composition.action-windows-v1`. Runtime 1.2 adds composition.action-timing-v1 for optional source-time mappings. Placement duration, collision checks and source duration validation use placementTiming; editor and runtime share loop-local mapping and 12-decimal interval boundary comparisons. Curves are evaluated at source time without baking. Project colors and orphan repair visit all source animations independently of context.

## Mutation contract

Outline appearance has one persisted owner: optional `Path.outlineSections`. References address contour/segment IDs and curve-local positions; generated stroke vertices never enter editable geometry or weight ownership. `OutlineEditingService` owns the editor scope, independent selection and cancellable drafts; `outline-preview.ts` supplies those drafts only to the live display. `outline-editing.ts` owns interval and taper edits, while the runtime's shared `curve-range.ts` and `outline.ts` project current (already deformed) contours. Canvas, static output, imperative playback and portable runtime use that projection. Inside/outside clipping is evaluated against the complete source fill, and outline paint gradients retain the source bounds.

Clipping-source paint uses the source's existing `visible` state. `render-projection.ts` owns the shared geometry/fill/stroke instance identities and paint-pass rules: geometry always clips, fill paints behind contents, and stroke paints above contents outside its own clip. Projection roots reference one document target through `data-render-target`; runtime render-role helpers update every instance without copying document geometry or weights. Layer commands initialize sources hidden and reveal them when releasing clipping. The shared geometry-availability helper keeps hidden clipping sources bindable and poseable, while ordinary hidden ancestors and locked layers remain unavailable. Document v17 migrates legacy clip sources and their visibility keys to hidden paint without changing their clipping geometry.

`ElementFactory.cloneSelection` returns typed ID mappings consumed by `LayerOperationsService.duplicateMany`; rig owners, attachments, clips and scene/action channels are remapped through that structural boundary. `LayerCommandService` owns selection and the single document commit. `path-topology.ts` centralizes binding, geometry-animation and outline-remapping restrictions. The Select tool delegates persistent topology commands through its document-mutation callback.

Persistent edits to the active document must finish at `DocumentMutationService`. Gallery import/delete/restore are project lifecycle operations owned by `ProjectService`, outside document history. `commit()` evaluates the animation base state and does nothing if it is unchanged. A real change captures one plain save and reuses it for one history entry and one project upsert. Mutation domains are `artwork`, `animation`, `guides`, `metadata`, and `thumbnail-artwork`. Only artwork-affecting domains invalidate the artwork plan and request an idle thumbnail refresh; animation-only changes retain the current thumbnail. Debounced controls call `schedule()`; structural commands mutate through their domain service and then commit.

History snapshots structurally share unchanged identity, artwork, animation, and guide sections. The per-document limits are 50 entries and 64 MiB of unique serialized section data; the oldest entries are evicted when either limit is exceeded. Gesture previews may mutate live state, but pointer-up commits exactly once, Escape restores the captured values, and no-op gestures commit nothing.

Undo and redo run against base animation state, restore every selected layer and nested point/line selection by stable IDs, reset the comparison baseline, and persist the restored document.

Viewport position, zoom, current time, tool choice, expanded rows, dialogs, and context menus are session/UI state and do not belong in document history.

`EditorPreferencesService` owns validated drawing defaults: solid fill/stroke persisted as color strings or null, plus one stroke width; `setDrawingPaint` merges partial updates. `EditorService.drawingPaint` exposes detached snapshots to drawing tools. `drawing-paint.ts` applies fresh Color instances and the default stroke width only to newly authored geometry, preserving model/import/clone defaults. Shapes, Pen, and construction previews capture the defaults when drawing starts; built regions capture them on creation. Pen retains a disabled fill until closure. Tools that author with these defaults set `Tool.usesDrawingPaint`; the header shows `DrawingColorsComponent` only while `EditorService.activeTool` is one of them, keeping creation defaults out of the selection sidebar. Otherwise an Edit-mode selection shows `SelectionActionsComponent` in that same contextual header slot. `DrawingColorsComponent` owns the fill/stroke chips, swap, width field, and a fixed popover with local color drafts that reuses `ColorAttribute` and `ProjectColorsComponent`; Escape, outside presses, and tool/document changes discard the draft, while the eyedropper shield keeps it open. Applying a drawing default updates preferences and remembers its color in the current document through `ProjectColorsService`. New artwork still commits through each tool's existing mutation boundary.

`SVG.projectColors` owns the unified retained palette, names, pins, and reuse order; history shares it as an independent section. `project-colors.ts` validates/canonicalizes values and discovers authored colors by stable usage keys, including nested/hidden/locked artwork, gradient opacity, and structured color keyframes. `DocumentMutationService.commit` collects changed colors from the captured animation base save and previous baseline only after a real change, adding palette data to that same history entry/autosave. The previous baseline preserves colors when their last object is deleted. Coalesced paint inputs collect the committed value; playback and canceled previews never enter the palette through rendering. Redo stores the restored snapshot as the current history entry so a subsequent edit undoes to that state.

`ProjectColorsService` owns palette commands and a cached projection of retained plus currently authored colors, with pinned favorites first. The mutation revision is reactive so palette instances inside unchanged OnPush paint editors refresh after edits and undo/redo. `ProjectColorsComponent` is the shared swatch/name/pin UI; `PaintEditorComponent` routes a chosen value through its existing paint events for properties, gradient stops, and timeline editors. Drawing color drafts stage swatch choices until Apply. Palette metadata edits use the metadata mutation domain; there is no global recent-color store, linked recoloring, or export/runtime palette data.

## Model compatibility

This cleanup intentionally retains the current constructors and serialized schema. Model constructors still accept `EditorService`; new construction must go through `ElementFactory` so a later schema-focused pass can remove that dependency without another UI-wide rewrite.

Persisted documents use envelope version 17 and animation schema version 2. Version 17 separates clipping-source paint visibility from clipping geometry; version 16 preserves legacy inferred path closure and adds optional outline sections. Version 15 enables authored bone/control channels and migrates v14 without changing rig values or artwork. Sequential migrators accept historic raw project arrays and document envelope versions 1–16; v1 animation data is upgraded without introducing temporal handles, and v4 artwork receives center-aligned solid-stroke defaults, so existing output remains visually and semantically unchanged. Version 14 adds rig schema v5 with optional canonical-owner `lockedBoneIds`; migration preserves legacy weights, including deliberately empty single-bone points, without inferring locks or rigid assignments. Version 13 adds rig schema v4 with optional group scope IDs, explicit cross-path shared weight owners and independent handle weights; legacy anchor inheritance and existing separate weights remain unchanged, with no inferred links. Version 12 adds rig schema v3 with optional persistent two-bone target constraints and their evaluation suspension flag; migration retains old poses without inventing links. Version 11 adds point bones, per-binding influence sets and rigid attachments in rig schema v2. Version 10 adds optional version-1 armatures, bones and point bindings. Version 9 adds optional source trim, positive rate and finite repetition to placements; omitted fields preserve full-duration 1× playback. Version 8 adds optional version-1 composition inside animation schema v2, with source-local animations and linked placements. Version 6 adds an optional embedded tracing reference; version 7 adds optional project colors with validated color strings, names, and pins. Older artwork is unchanged and absent editor metadata needs no new artwork defaults. Unsupported future versions are read-only to older clients and are never overwritten. Changes to `SVGSave`, element saves, or animation versions must add a sequential migrator and fixtures first. Existing IDs, shared `Point` identity, compound contours, clipping references, transforms, motion paths, and animation track targets are compatibility constraints.

`EyedropperService` owns one editor-scoped sampling session, source decoding, coordinate mapping, context validation, and preview state. `EyedropperSurfaceDirective` registers the displayed SVG; `EyedropperComponent` owns the fixed modal shield, source controls, keyboard/focus behavior, and magnifier. `ColorAttribute` routes accepted values through its normal accessor callback; the sampler flushes the resulting coalesced mutation so each confirmed pick is immediately undoable. Drawing-default drafts still commit only on Apply. Session start flushes pending edits and pauses playback; document, selection, tool, mode, time, history, or owner changes cancel sampling.

`color-sampling.ts` owns raster helpers. Artwork snapshots the displayed SVG with its canvas background, excluding temporary geometry and editor overlays, capped at 4096 pixels per side. Reference sampling decodes the embedded original image and maps its fitted placement independently of opacity and overlapping artwork. Each pointer sample reads an 11×11 pixel patch; alpha-zero and out-of-image samples are rejected. Snapshot rendering uses SVG image decoding, so external resources and unavailable fonts can differ or fail; there is no browser-specific screen-sampling dependency or persisted sampling state.

`ToolGroup` routes input and lifecycle to the remembered child for the Paths and Shapes palette groups. `Tool` owns child activation and sibling deselection; saved leaf tool keys restore within their current group. `ConstructionTool` is a palette adapter for the scoped `ConstructionDrawingService`, which owns line/arc pointer state, snapping, and temporary geometry. `ConstructionControlsComponent` binds the tools, projects passive origin/radius guides, and owns focused keyboard/cancellation lifecycle. Completed geometry inserts once through `LayerOperationsService.insertElement` inside `DocumentMutationService.mutate`; preview elements never serialize. `arc-geometry.ts` is the shared SVG endpoint-arc-to-cubic converter used by SVG import and arc construction. The existing ellipse tool handles circles via Shift and centered circles via Shift+Alt; arcs remain ordinary editable path contours.

`ReferenceImageService` owns file/clipboard raster ingestion and reference edits through metadata-domain document mutations. `EditorClipboardDirective` routes native copy/paste events, preserving text-control and dialog behavior; image bytes take precedence over the app-local object clipboard. Object copy writes an inert text marker to replace stale system images while keeping editable fragments app-local. Plain Ctrl/Cmd+C/V defer to native events; Shift+paste retains in-place object paste. `ReferencePanelComponent` owns the header button and its persistent popover (closed by its button, close control, or Escape; `panelOpen` lets image paste open it); `ReferenceOverlayComponent` owns pointer capture, projection, keyboard movement, cancellation, and proportional resizing. Gesture drafts stay outside the document until completion. `SVG.referenceImage` persists one validated embedded PNG/JPEG/WebP aid independently of artwork; history shares the source separately from placement so moving a large image does not duplicate its bytes. `SVGDisplay` receives the reference explicitly as editor presentation. Static SVG, runtime bundles, and thumbnails omit it; Project JSON includes it.

The primary repository is IndexedDB database `svg-animator`, with separate `projects`, `documents`, `thumbnails`, and `meta` stores. Metadata and document revisions commit in one transaction. Existing localStorage data migrates once and is retained as a read-only backup for one compatibility release. Repository creation falls back to the legacy localStorage format, then to an in-memory session with a persistent save warning. Saves, thumbnail updates, deletes, and restores share one ordered queue so a delayed write cannot undo deletion or recovery. The existing IndexedDB `meta` store records whether the gallery has been saved, distinguishing an intentionally empty gallery from a first launch without changing document or database versions. `ProjectService` owns a session-only deletion stack with complete record snapshots; no trash state is serialized.

## Rendering boundary

`AnimationInspectionService` shares session-only onion/trail controls between the timeline and workspace. It restores a detached model through `ElementFactory`, then uses `AnimationPlaybackService.restoreSamplingBase` to replace preview-mutated values only in that copy; the live document is explicitly rejected. `AnimationInspectionSnapshot` reuses `AnimationEvaluationPlan`, property adapters, geometry snapshots, origins, and motion matrices. Geometry/transform baselines reset before every sampled time. Ghost SVG markup is generated with full ancestor/reference geometry before unrelated rendered targets are removed, preserving computed transforms and clipping; isolated SVG images avoid duplicate live DOM IDs. The snapshot never invokes the live imperative renderer or mutation boundary.

Inspection caches invalidate on document identity, mutation/animation revisions, selection and relevant sample settings/time. Trail geometry uses 61 samples per selected origin (up to eight objects); pan/zoom use the shared workspace projection without recompiling samples. The overlay is passive, below edit handles, and hidden in Edit mode or playback. Images, controls and trail data do not serialize or enter exports. Scene, action and rig channels use the same evaluation boundary and detached sampling baselines.

Interactive authoring may include temporary drawing elements and editor overlays. `buildSVGMarkup()` is the static publishing/thumbnail boundary and must never emit editor handles or hit targets. Import preservation uses sanitized render representations; opaque source must never execute active content.

`SVGEditorOverlayComponent` owns the workspace SVG controls and their scoped presentation. It uses the shared canvas-to-workspace projection, outside the artwork SVG and its clipping masks. Handle sizing and segment hit widths are in screen pixels. Segment hit geometry is separate from its passive selection/hover highlight so selecting a segment never reduces its target area; input still flows to the existing tool and mutation owners. Shared selection frames come from `editor/selection.ts`; ancestor/descendant filtering, parent-space bounds, and transform availability are shared with `SelectionTransformInteraction`. Multi-object resizing stays proportional to avoid introducing skew into the existing transform schema.

`MoveSnapSession` in `snapping.object.ts` owns pure acquisition/release math and feedback. `MoveSnappingInteraction` freezes arrangement bounds and eligible targets at pointer-down; `TransformInteraction` applies its corrected canvas point to either single-object or selection movement. Targets exclude moving subtrees and ancestors but include visible locked references. Motion-driven moving geometry is excluded. Alt refreshes remain inside the canvas gesture, avoiding keyboard-triggered history entries. Feedback exists only in the workspace overlay, never in saved documents or exports. The preference is stored with editor settings and requires no document migration.

`path-snapping.ts` projects eligible path anchors, segment midpoints, and segment control geometry into canvas space, excluding the moving anchor and segments it deforms. `PointSnapSession` captures both coordinates of a discrete point with radial hysteresis. Interior captures reproject onto the same segment while within release tolerance, with nearby discrete targets taking precedence; guide/canvas fallback reuses `MoveSnapSession`. Cubic evaluation lives in `curve-geometry.ts`, shared with motion-path sampling. Clipped groups and rounded vertices/adjacent segments are conservatively excluded until rendered-outline queries are available.

`PathGeometryQuery` reuses the installed Paper engine for finite-segment nearest locations and intersections, including self-crossings. Standalone curves allocate no Paper project or scene items. Frozen canvas-space control geometry gives nearest-point queries the correct metric under nested nonuniform transforms. Nearby bounds filter pair queries; intersection results are cached per session and overlapping continua are excluded. Queries do not mutate or split document geometry. Karma loads the same Paper core as the app so tests exercise the actual curve engine and adjacent stroke booleans.

`curve-constraints.ts` solves cross/dot-product conditions between a cubic's tangent and the vector from a fixed construction origin. Normalized coefficients and derivative-root partitions handle finite roots and repeated contacts; cusps, zero-length connections, and continua are excluded. `PenTool` supplies a construction origin only for straight segments. `PointSnapSession` incorporates these fixed contacts into the existing radial capture logic; coincident anchors/intersections take precedence, then construction contacts, then midpoints. No new document constraint state is introduced.

Native circles/ellipses enter the same target snapshot as a canvas-space center and two transformed radius vectors. `ellipse-geometry.ts` maps the line origin into the unit circle, solves its two tangent contacts analytically, then projects them back. `PathGeometryQuery` freezes these targets and returns contacts alongside path contacts. This preserves tangency under general nonsingular ancestor transforms without introducing approximate cubic geometry. Perpendicular contacts use two rational half-ellipse parameterizations and the shared `polynomial-roots.ts` solver to find finite roots of the canvas-space normal condition. Solving after projection preserves right angles under nonuniform scale and shear. Repeated roots are retained; zero-length connections and infinite contact families are excluded. Both kinds enter the existing fixed-origin contact snapshot and feedback lifecycle. Native interior/intersection queries remain separate.

`flatEdges` reuses path snapshots and adds the rendered straight portions of rectangle sides. `EdgeRotationSnapSession` maps moving/reference edges into the gesture's rotation frame, solves parallel orientation modulo 180°, and projects aligned edges back to canvas space for feedback. Single and selection transform owners apply its corrected angle through their existing baseline/pivot logic. Sessions clear on finish/cancellation; Alt refreshes reuse the stored pointer without committing. Multi-object Shift increments bypass edge capture. `SnapFeedbackOverlayComponent` renders the same passive lines and labels for rotation feedback.

`PointSnappingInteraction` owns the common session lifecycle. `PenTool` refreshes targets between placements and keeps a captured target through mouseup until click commits. `PathAnchorInteraction` freezes the pointer offset, inverse transform, geometry, and ancestor origins; it restores that baseline before each preview and on cancellation. The canvas and animation gesture owners retain the single mutation boundary. Alt-before-drag conversion stays in `SelectTool`; Alt-during-drag bypass stays inside the anchor gesture.

`SnapFeedbackOverlayComponent` projects object and point feedback into the same workspace surface, with fixed screen-size markers and labels clamped below the rulers. Snap sessions remain transient; the existing `objectSnapping` preference key now controls both consumers without changing saved document formats.

Rulers stay in the artwork's template view so SVG host dimensions are applied before measurements. Ruler viewport culling is sampled once per check, keeping sibling-panel layout changes from changing bindings midway through a render; CSS clips excess marks.

`AnimationGestureService` captures all selected targets before any keyframe upsert, because upserts may restore/reapply preview values across the entire document.

Arrangement uses geometry bounds, including curve extrema and transformed ellipses, without changing the historical control-hull bounds used for automatic transform origins. Strokes and effects are excluded; clipping uses intersected geometry bounding boxes. Translations capture every parent matrix/origin before changing any child. Clipboard snapshots retain necessary ancestor groups, clipping masks, motion-path dependencies, and animation tracks. Pruned parent groups pin their base-state origin; pasting does not reproduce origin changes caused by omitted animated siblings. Referenced paths outside the copied artwork are included hidden. ID remapping covers geometry/paint IDs, animation targets/properties, and sanitized SVG resource references through the same reference helper as SVG import. No new serialized schema is introduced.

The object clipboard lasts across project navigation within one app tab until reload; it does not read or write the operating-system clipboard. Edit-mode shortcuts own object copy/paste while Animate mode retains timeline keyframe shortcuts. Text editors keep native clipboard behavior.

Animation playback has a separate retained rendering path. `AnimationEvaluationPlan` flattens targets and compiles sorted track data into typed arrays. Forward playback advances active-segment cursors; seeks and reverse movement use binary search. `ImperativeSvgRenderer` caches stable SVG nodes and batches attributes outside Angular so transform, path, paint, gradient, and progress channels produce consolidated DOM writes. Angular remains authoritative for paused authoring, and preview-mutated values are never serialized.

`compileRuntimeAnimation()` is a pure export boundary, not a persisted cache. It emits `RuntimeBundleV1` with normalized scene descriptors—including resolved and automatic transform-origin semantics—and compact numeric, packed-color, and discrete tracks; diagnostics remain outside the portable bundle. Runtime-bound markup opts into deterministic IDs/render roles while `buildSVGMarkup()` retains its script-free static output. `packages/runtime` has no Angular/editor-model dependency and is the shared framework-free evaluator/DOM player contract.

### Construction regions and independent trimming

`ShapeBuildingTool` only forwards palette input. The editor-scoped `ShapeBuildingService` owns frozen geometry, region selection, trim hover, scope, invalidation, and completed commands; `ShapeBuildingControlsComponent` owns overlay projection and tool binding; `bindToolKeyboard` shares focus-aware Enter/Escape/history handling with construction controls. `constructionSources` projects eligible static model outlines to canvas coordinates, preserving full precision for ordinary paths and baking rounded corners. `ConstructionNetwork` splits curves at intersections, traverses directed boundaries to discover bounded regions/holes, and groups original-contour spans for standalone trimming. Native ellipse snapshots retain their affine axes alongside dense intersection geometry; editable region/trim output coalesces consecutive ellipse pieces through the shared `ellipseArcToCubics` converter, without simplifying authored Béziers. Region containment keeps the dense query geometry. Vertex incidence counts both ends of touching edges so tangent lines split trim spans in either drawing direction. Paper objects are disposable snapshots and never enter persisted state.

`paper-geometry.ts` centralizes Paper scope lifetime and native contour conversion shared with the existing boolean owner. Region unions use `unionFilledPathRegions`, which preserves holes within each region. Created paths use `ElementFactory`, structural inserts/replacements/deletions use `LayerOperationsService`, and each completed action commits through `DocumentMutationService`. Trim coordinates return through the inverse source transform; pinned ancestor/source origins prevent sibling movement after bounds change. Undo, mode/document changes, revisions, tool changes, and destruction invalidate transient geometry. Previews do not serialize or affect export.

`ellipse-geometry.ts` also owns nearest analytic ellipse contacts, length-preserving tangent handle alignment, and common support-line contacts. Point snap candidates can carry a tangent direction or a paired origin; `PenTool`, `PathAnchorInteraction`, and `ConstructionDrawingService` apply that information within their existing gesture ownership. Only the first straight Pen segment may move its starting anchor for a common tangent, avoiding unintended deformation of earlier segments. These edits introduce no persistent geometric constraints.

### Armatures and pose evaluation

`RigEditingService` owns persistent rig commands through `DocumentMutationService`; selected rig/bone/anchor and Edit/Pose/Weights workspace are session state. `armature.ts` owns schema validation, parent-local FK and linear weighted deformation. `rig-binding.ts` owns stable point/control associations, topology checks and applying poses. Rig panel and overlay own presentation and temporary pointer drafts. Rig snapshots participate in history sharing, autosave and Project JSON.

Binding captures rest-local point coordinates and the path-to-canvas matrix, pinning existing automatic origins throughout the ancestor chain. Weighted deformation transforms rest points through canvas-space posed × inverse-rest bone matrices and back into path space. Handles inherit their corresponding anchor weights unless explicitly independent; an empty effective weight set leaves any point at rest. The current static pose is materialized in path geometry, while original rest points remain in bindings. Rendering and static/runtime export therefore consume the same posed base artwork without another evaluator. This is not bone animation support.

Pose commands validate all bound paths before writing: missing points, changed topology/transforms, hand-edited geometry, or locked/hidden paths block the command. Unbind preserves current geometry. Edit gestures rebase the visible rig to a rest setup through `rig-rest-edit.ts`, retaining artwork, stable IDs and weights; optional parent-local `poseX`/`poseY` offsets support root/body translation and default to zero for older saves. Bound bones cannot be deleted; deleting parents requires explicit child reparenting/removal. Initial binding rejects existing animation tracks on the path/ancestors and motion-path constraints. Future rig channels must specify ordering with direct geometry animation and extend runtime parity before shipping.

### Rig authoring UX and rigid attachments

Document v11 / rig schema v2 adds explicit zero-length point bones, optional per-binding influence sets and rigid attachment records. Missing bone kind remains a length bone; legacy hierarchies are preserved. New rigs use the armature ID/name for a point root. `BoneDrawingService` owns temporary strokes and delegates one completed command to `RigEditingService`; the palette adapter and canvas controls contain no persistent mutation. `RigBindingSessionService` owns cancellable artwork-first influence picking. The existing layer stack remains the sole draw-order owner; bone rows and relation badges only project rig metadata.

Rigid links capture parent/world matrices and the rest transform without reparenting artwork. `rig-attachments.ts` derives the posed local transform, preflights representability using the shared affine decomposition helper, and applies it in the same transaction as bone posing. Geometry, groups, clipping and layer order stay intact. Detach leaves the current transform. Skew-producing poses are rejected before writing, consistent with the native transform model; overlapping ancestor/descendant rig links are rejected. Static poses remain ordinary SVG transforms for existing rendering/export paths.

Bone Layers owns temporary inline rename UI and uses the shared editor context menu for rename, reparent, unlink and deletion commands. RigEditingService owns metadata-only rename and canvas-preserving reparent mutations; row menus never mutate the artwork hierarchy. Properties retains numeric rig editing and Reset pose; the separate Binding & weights workspace owns weight presentation.

Artwork and bone layer handles share `RowPointerDrag` capture/threshold behavior and drop-zone geometry. Bone drops commit through RigEditingService, preserve canvas placement on reparenting, and reorder only rig metadata. Drag sessions cancel on document, revision, mode, or binding-context changes.

The framework-free kernel in `packages/runtime/src/rig` owns the analytic two-link solver, connected-chain checks, FK matrices, weighted deformation and rigid attachments. Existing editor module paths re-export these implementations. Its constraint plan validates persistent references, target ancestry, duplicate writers and dependency cycles, and derives deterministic solve ordering. Constraint evaluation retains authored pose values and returns the solved skeleton. `RigEditingService` preflights evaluated poses and commits setup commands, constraint metadata and materialized weighted/rigid artwork through one mutation boundary. Animation and action channels evaluate first, followed by authored FK → constraints → weighted geometry and rigid transforms. Static rendering/export still consumes materialized base artwork.

### Bone channels, reusable rig actions and publishing

Rig tracks reuse animation schema v2: `targetId` is the armature ID and `property` is `bones.<boneId>.pose`, `.poseX` or `.poseY`. Values are numeric authored rotation offsets in degrees and translations in the bone parent's coordinates. Rest transforms, lengths, weights and constraint settings are setup state. The shared `rig/channels.ts` parser owns channel addressing; `rig-animation.ts` adds document read/write adapters while keeping artwork-only adapters unchanged. `AnimationEvaluationPlan` accepts an optional `RigDocument`, preserves its artwork `targetMap`, and resolves rig source windows through the existing action-composition evaluator.

`RigEditingService` routes Animate-mode pose gestures into the active scene/action tracks. It keys changed authored controls, never the angles produced by a persistent IK solve. Enabled IK chain bones cannot receive competing pose channels; users animate the target. Canvas, numeric and timeline controls share this rule and action target scope. Gesture completion submits all changed channels through one document mutation. Cancellation, context/time changes and history discard temporary pose output. Bone setup and weight editing remain Edit-mode operations.

`AnimationPlaybackService` captures the base before writing channels, then materializes each animated rig once after all channel values have been applied. `rig-animation-preview.ts` captures optional bone offsets, setup suspension, bound point coordinates and attachment transforms by stable IDs; restoration works on the live document or a same-ID detached copy. Saved base artwork and bind data therefore remain independent from preview geometry. Enabled IK evaluates during animation even when the last setup operation suspended posing; this does not persist a changed suspension flag. Detached inspection restores the same baselines before every random/backward seek and includes artwork controlled by animated rigs in onion skins.

Actions target armature IDs alongside existing artwork IDs. A selected armature can create an empty action or extract its scene keys; placements retain existing source trim, rate, repeat and direct/base fallback semantics. This is reuse within one document, without retargeting bones by name or creating actor instances. `documentRigChannelProblem` adapts document hierarchy to the shared conflict checker: animated rigs cannot simultaneously accept geometry, point, transform or motion-path tracks on controlled artwork/ancestors. Style, opacity and visibility remain compatible. Missing bone references are orphaned channels and block enabled animated publishing.

Runtime 1.3 extends bundle v1 with optional `rigs` and the required `rig.pose-v1` capability when bone channels are active. The compiler preserves numeric channels and action windows exactly; it does not bake points per frame. Editor and player consume the same rig kernel. Runtime validation checks capability support, rig/scene references, topology and conflicting writers before changing SVG output. Static SVG has no live rig evaluator. Bone scale, keyed constraint enable/bend/mix, physics, IK stretching, cross-rig targeting and actor retargeting remain separate work.

Rig schema v3 stores named `TwoBoneIKConstraint` records with upper/lower/target IDs, enabled state and bend direction. Optional `constraintsActive` defaults to active and preserves a suspended setup across save/reload. Edit rest changes rebase visible geometry and suspend solving; entering Pose resumes it. Constraint setup in Edit preserves the visible pose. Match target to tip explicitly aligns a control; Reset in Edit clears authored offsets with solving suspended, while Reset in Pose clears offsets and evaluates the enabled constraints. Removing a constraint retains the visible limb as authored FK. Constraints remain independent of bone selection and artwork draw order.

`RigConstraintsComponent` presents the same constraint from either chain bone or target, lists every armature constraint with its state, and explains why a selected bone cannot start IK. `constraintIssue`/`constraintJointGap` in `rig-constraints.ts` (sharing structural checks with `constraintPlan`) name the first problem per constraint; a drifted joint is repaired by `RigEditingService.moveJoint`, backed by the pure `moveBoneJoint` in `rig-rest-edit.ts`, which re-aims the parent to the joint while the child's tail and all other bones keep their canvas placement. Bone setup body drags and arrow nudges of a connected length bone move that shared joint; numeric edits that would separate a constrained joint are refused. `BoneDrawingService` starts a new bone exactly on the selected bone's tip within 12 screen pixels, so drawn chains connect. `RigEditingService.ikPick` is session-only target picking: `RigBindingSessionService.toggle` routes canvas and Layers bone clicks to `pickIKTarget`, the overlay highlights `ikTargetCandidates` (bones that neither ride on nor carry the chain), and any revision, document, rig or Weights change makes it inactive. `REST_REQUIRED` in `rig-rest-edit.ts` is the shared refusal for binding, attaching and drawing while authored poses or IK bend the skeleton; `resetToRest` clears poses and suspends IK, and `RigBindingSessionService.resetToRest` restarts assignment picking with the same bones. `IKTargetComponent` owns cancellable pointer/keyboard gestures at the actual target point, while `RigEditingService.posePreview` feeds the existing skeleton overlay. Pose gestures (FK tips/bodies and IK targets) and numeric/automatic weight previews on a posed rig temporarily write the evaluated pose into the live bound artwork and attachment transforms, snapshotting it first; cancellation restores the snapshot exactly, and every rig command restores it before its single commit. Previews never commit, autosave or enter history. Brush strokes keep colour-only previews because their hit-testing uses frozen point positions. The open Weights workspace owns the inspector (`RigEditingService.ownsInspector`), replacing artwork properties whose edits would invalidate bindings; `RigBindingSessionService.showsBindingControls` limits the binding block to selected artwork, or to bone-first scope in Weights. The target remains at its requested position when the limb clamps to its reachable range. Unlinked pairs retain the session-only quick-pose handle; that path stores solved FK poses without manufacturing persistent links.

`RigBindingSessionService` owns artwork/group scope, bone-first reverse scope, canonical selected owners, the raw inspected point, cancellable assignment picking, brush settings and all temporary weight previews. Artwork-layer selection updates artwork-first scope; bone selection retains it. `RigBindingControlsComponent` composes Assign bones / Edit bones with `RigWeightsPanelComponent`; zero/one/multiple assignments infer unbound/rigid/weighted behavior. Native paths keep point bindings when rigid so handle/owner metadata survives; non-path artwork uses transform attachments. `RigEditingService` owns complete assignment preflight and one persistent commit, including rest-only attachment conversion. `rig-artwork-scope.ts` projects native descendant paths and clipping paths without changing hierarchy or draw order. `PathBinding.scopeId` records group setup ownership.

Rig v4 separates `BoundPoint.anchorId` geometry ownership from optional `weightSource: {pathId, pointId}` weight ownership. Anchors and explicitly independent handles can own normalized weights or refer directly to a canonical owner in the same armature. Nonowners store empty local arrays. `weightOwner` and `effectivePointWeights` are the only resolution boundary used by deformation, numeric editing and overlay projection. Validation rejects dangling/cyclic/noncanonical links, missing influences, invalid sums and weights outside any member path's declared influence set. An independent handle's empty weights never fall back to its anchor.

`rig-point-weights.ts` owns immutable link/unlink, handle inheritance and binding removal operations. Coincident linking compares exact captured rest positions after each binding matrix, never posed geometry or rounded screen coordinates. Existing IDs, contours and path points remain independent. Joining sets keeps the first canonical owner's values and unions allowed influences, rejecting conflicting locked values. Separating a point copies its effective values and locks. Removing an owner or restoring its handle inheritance rehomes surviving shared members before deleting the link. Persisted ownership survives rest edits instead of being inferred again from current positions.

`rig-weight-editing.ts` is the pure boundary for effective owner state, shared-member allowed-bone intersections, rigid/custom classification, locked-budget normalization and automatic weighting. Numeric and brush edits preserve locked values exactly, distribute the remaining budget proportionally, and use equal shares when all other eligible values are zero. Automatic weighting uses captured rest-world positions and the two nearest eligible bone segments (point bones have zero length), inverse-square distances and stable ID tie ordering. New weighted assignments initialize automatically; existing weighted assignments retain manual values. Explicit legacy bindings with empty weights remain custom; loading does not rewrite them.

`rig-weight-commands.ts` resolves numeric/brush updates to canonical owners once, rejects conflicting writes or changes to locked values and preserves array order on semantic no-ops. Influence changes account for shared-member memberships and locked values; unrelated points retain their weights. `RigEditingService` validates full candidates and materializes evaluated poses through the existing single mutation boundary. Group assignment, lock changes, clearing weights, unlinking and completed edits each commit once. `rig-weight-colors.ts` provides stable bone colors shared by the legend and canvas overlays.

`WeightBrushStroke` in `rig-weight-brush.ts` owns frozen screen-space samples, weights, memberships and locks, segment coverage, strongest-pass owner deduplication, and Add/Subtract/Set/Smooth math through `editWeightInfluence`. `RigWeightOverlayComponent` owns pointer capture, projected points/handle lines, marquee drafts, keyboard dabs, overlap inspection and cancellation; session state owns the selected owners and every numeric/automatic/brush weight preview. A nonempty selection restricts brush eligibility; rigid owners are excluded. Inherited handle hits resolve to their anchor owner. Release submits one set of owner updates; Escape, pointer loss, blur, history and scope/selection/view changes discard drafts. No-op strokes do not mutate the document. Bone-first filtering can show positive weights or all eligible points including zero weights. Screen-position clusters are presentation only: independent owners remain separate rows in the bounded overlap popover, support additive selection and lock-aware editing, and never merge implicitly. Weight settings, selections, previews and popovers never serialize or export. `WEIGHT_TOOLS`, `BRUSH_LIMITS`, `setPaintMode`, `setBrush` and the shortcut steps in `RigBindingSessionService` are the single owner of tool and brush state for the panel tool bar, the canvas HUD and the 1–5 / [ ] shortcuts. The overlay captures those keys before document-level artwork shortcuts only while weights are editable and focus is outside text fields. `weightDisplay` (Mix/Heat) is session-only presentation; `weightHeatColor` in `rig-weight-colors.ts` owns the ramp. Rig panels share `rig-panel.scss` section, segmented, field and HUD styles built on the existing tokens. Bone/action channels and animated rig evaluation/export use the shared pipeline described above; physics and broader constraint controls remain future work.
