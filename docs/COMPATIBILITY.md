# Compatibility policy

The editor app and standalone runtime are independently versioned with SemVer. Removing or renaming runtime exports, changing method/event semantics, narrowing accepted inputs, or changing defaults is breaking. Public API is deprecated for at least one minor release before removal in the next major, with a replacement recorded in the changelog and migration guide.

`RuntimeBundleV1` uses integer format version 1. Optional metadata is additive. Required structural or semantic changes increment the format. Each runtime major supports its own bundle generation and the immediately previous generation through explicit adapters. Unsupported capabilities and future formats fail before SVG mutation.

Persisted editor documents use sequential migrations indefinitely. Unknown future versions are never overwritten, and compiled runtime caches are never persisted in editable documents. Before changing a document, animation, bundle, or API contract: freeze the old fixture; add migration/adapter coverage; update schema, API report, changelog, and migration docs; then bump the applicable version.

Current editor documents use envelope 17 with animation schema 2 and rig schema 5. Migration 17 hides legacy clipping-source artwork and makes its existing scene/action visibility keys false while preserving channel/key identity, timing and action scopes. Other artwork visibility is unchanged. Current documents retain source visibility exactly; its eye toggle controls paint while clipping geometry remains active. Imported SVG clipping roots start hidden, and explicitly hidden descendants retain their geometry visibility.

The private registry package name is not a compatibility contract. `SVGAnimatorRuntime` is stable and must remain as an alias after any rebrand.

Runtime 1.3 keeps bundle format 1 and adds the optional `rig.pose-v1` capability plus `rigs` metadata. Runtimes 1.0–1.2 reject this capability instead of displaying silently frozen bones. Bundles without animated rig channels keep their prior shape and behavior. Runtime and editor share FK, IK, weighted deformation and attachment math; rest data and authored offsets remain separate from each evaluated frame.

Runtime 1.4 adds `render.outline-sections-v1` within bundle format 1. It is required for paths with authored outline sections or explicit open contours whose endpoints coincide or can meet during geometry/rig animation. Missing `path.outlineSections` retains the previous full stroke and Draw Progress behavior; an empty list hides only the stroke. Sections address stable contour/segment IDs and curve-local positions, including implicit closing edges. Their generated stroke vertices are renderer output, never saved geometry or weighted points. Older runtimes reject the capability before mutation. Existing portable bundles without the capability retain legacy inferred closure; newly compiled explicitly open contours carry `path.explicitClosure` when needed. Editor document migration 16 preserves the prior inferred-closure appearance before making contour flags authoritative.

Runtime 1.5 adds `render.visible-clipping-v1` within bundle format 1. New clipping exports require it so older players reject the new paint/geometry visibility semantics before mutation. Bundles without it keep legacy clipping behavior. Visible clipping artwork is derived from the same animated source geometry and transform as its clipping boundary; generated paint instances do not become document layers or rig targets.
